# PROJECT_RULES.md — прочитай ЦЕЛИКОМ перед любой работой

Ты помогаешь разрабатывать проект **OoverrFinancee** — семейный финансовый трекер.
Это **монорепозиторий на TypeScript**: веб-дашборд (`apps/web`), Telegram-бот (`apps/bot`) и общий пакет (`packages/shared`), связанные через облачную БД **Supabase**.
Фактическая архитектура — в [`ARCHITECTURE.md`](./ARCHITECTURE.md), схема БД — в [`DATABASE.md`](./DATABASE.md), порядок разработки — в [`ROADMAP.md`](./ROADMAP.md). Эти документы — источник правды; если здесь и там расхождение, доверяй `ARCHITECTURE.md` и предупреди меня.

Я НЕ программист и вставляю твой код в VS Code вручную. Ты НЕ видишь мой проект, только то, что я вставил в этот чат.

## 1. Главные правила

1. Работай ТОЛЬКО с файлами, которые я назвал в задаче. Ничего не переписывай и не «улучшай» заодно.
2. Если для задачи нужен файл, которого я не вставил, — СПРОСИ его. Не придумывай его содержимое.
3. Не меняй схему БД, имена функций, имена файлов и `.env` без моего явного согласия. Если это необходимо — сначала объясни зачем и жди ответа.
4. Сначала дай короткий план (3–5 строк), потом код.
5. Если задача слишком большая — предложи разбить на шаги и сделай только первый.
6. Не удаляй существующий код, который не относится к задаче.

## 2. Технологический стек (актуальный — НЕ Python)

- **Язык/рантайм:** TypeScript (strict), Node.js 20+.
- **Монорепозиторий:** npm workspaces (`packages/*`, `apps/*`), тип `module`. Зависимости ставятся одной командой `npm install` в корне.
- **Дашборд** (`apps/web`): React 19 + Vite 8 + Tailwind CSS v4 (`@tailwindcss/vite`), иконки `lucide-react`, анимации `motion`, данные `@tanstack/react-query`.
- **Бот** (`apps/bot`): GrammY (`@grammyjs/*`) — ⏳ пока не создан (ROADMAP 1.7+).
- **БД:** Supabase (PostgreSQL + Auth + Realtime + RLS), клиент `@supabase/supabase-js`.
- **LLM / распознавание голоса:** Google Gemini через `@google/genai` (один ключ на парсер и транскрипцию). Groq/Whisper больше не используется.
- **Деньги:** `decimal.js` (никакого `float`); в БД `numeric(14,2)`.
- **Время:** хранение в UTC (`timestamptz`), а «сутки/неделя/месяц» считаются по **Europe/Kyiv** через `date-fns` + `date-fns-tz`.
- **Валидация ответов LLM:** `zod` (проверка JSON от Gemini до использования).

> ❌ В проекте НЕТ и не должно появляться: Python, `aiogram`, `Streamlit`, `Groq`, `sqlite3`, `pip`. Всё это — из старого плана, удалено.

### Правила слоёв (нарушать нельзя)

```
apps/web  ─┐
           ├──►  @oover/shared  ──►  Supabase (PostgreSQL)
apps/bot  ─┘        (типы, деньги, время, формулы, парсер, клиенты/мапперы БД)
```

- `apps/web` и `apps/bot` **никогда не импортируют друг друга** — общий код только через `@oover/shared`.
- **Бизнес-формулы** (балансы, Net Worth, Safe-to-spend, сравнение месяцев) — только в `packages/shared/src/calculations.ts`. UI не считает деньги сам, он вызывает эти функции.
- **Деньги — только через `money.ts`** (decimal.js). **Время и границы суток — только через `time.ts`** (Europe/Kyiv).
- **SQL и работа с БД — только через `shared/src/supabase/*`** (клиенты и мапперы). Таблицы и политики — в `supabase/schema.sql`.
- `@oover/shared` не знает ни про React, ни про Telegram — это чистый TypeScript без DOM/Telegram-зависимостей.

## 4. Формат ответа

- Каждый изменённый файл — **полностью**, от первой до последней строки, в отдельном блоке с путём в заголовке (например `apps/web/src/views/OverviewView.tsx`). Никаких «...остальной код без изменений».
- В конце ответа:
  - **Изменены файлы:** список
  - **Не тронуто:** что намеренно не менял
  - **Как проверить:** конкретные шаги (какую команду запустить: `npm run typecheck` / `npm run dev:web`, что нажать, что должно появиться)
  - **Что установить:** новые библиотеки, если есть (`npm install <пакет>`; уточни, в какой пакет — `apps/*` или `packages/shared`)
- Если ответ ожидаемо длинный — раздели на части и спроси, продолжать ли.

## 5. Неизменные решения

- Стек — из раздела 2 (TypeScript + npm workspaces + React/Vite + Supabase + grammY + Gemini). Python-стек удалён окончательно.
- **Деньги:** `numeric(14,2)`, не `float`. Валюты: UAH (по умолчанию) и USD; курс USD вводится вручную (ключ `usd_rate` в таблице `settings`).
- **Время:** хранится в UTC, но «сегодня» и границы дня считаются по Europe/Kyiv (ключ `timezone` в `settings`, дефолт `Europe/Kyiv`).
- **Баланс счёта вычисляется** из операций, а не хранится. Переводы между счетами — отдельная таблица `transfers`.
- **Идемпотентность:** уникальный индекс `uq_tx_telegram (telegram_chat_id, telegram_message_id)` в `transactions` (где `telegram_message_id is not null`); вставка — с `ON CONFLICT DO NOTHING`. Плюс таблица `processed_updates` защищает от повторов апдейтов Telegram.
- **Парсер:** каскад `Gemini LLM → regex-фоллбэк → needs_review` (`parseInput` в `@oover/shared`). Бот не должен терять ввод ни при каких сбоях внешнего API.
- **Бот приватный:** whitelist из Telegram ID (`ALLOWED_TELEGRAM_IDS` в `.env`). Секреты только в `.env`, никогда в коде и не проси меня вставлять их в чат.
- **Ключи по контексту:** `service_role` — только на сервере бота; в браузере — только `anon` + RLS; `GEMINI_API_KEY` — только сервер (бот) или Edge Function, **никогда** в браузерном бандле. В `vite.config.ts` в бандл пробрасываются **только** `SUPABASE_URL` и `SUPABASE_ANON_KEY`.
- **Интерфейс на русском.** Дизайн дашборда минималистичный (Notion / Obsidian).
- **Хранилище дашборда:** Supabase — единый источник правды (anon-ключ + RLS, вход по email/паролю через `services/auth.ts`, данные через `services/data.ts`). `localStorage` для данных не используется. Не «улучшай» это без согласия.
- **Вне MVP:** долги, фото чеков, круговые диаграммы, автокурс валют.

## 6.1. Критичные ловушки (проверяй свой код на них)

- **Время:** никаких ручных границ суток через `new Date()` / `date-fns` / `toISOString().slice(...)`. Границы «сегодня/неделя/месяц» — только через `shared/time.ts` (`todayYmd`, `startOfDay/endOfDay`, `rangeForPreset`). Хранение в UTC.
- **Секреты:** токены и ключи только из `.env`. Никогда не вписывай их в код. В браузер не должны попадать `SUPABASE_SERVICE_ROLE_KEY` и `GEMINI_API_KEY`.
- **Деньги:** только `decimal.js` (`toDecimal`/`round2`/`sumMoney`/`convertToUah` из `money.ts`) и `numeric(14,2)` в БД. Никакого `float` для сумм.
- **Дубли:** вставка транзакции из Telegram — только идемпотентная (`ON CONFLICT DO NOTHING` + `processed_updates`).
- **Бот не должен падать на мусоре:** любой непонятный ввод = статус `needs_review`, а не ошибка. Сбой Gemini обязан быть пойман и приведён к regex-фоллбэку (не «проглатываться» молча).
- **Пустые данные:** если нет `next_income_date` или стартовых остатков, покажи понятное сообщение, а не ошибку или странную цифру.
- **Состояние диалога бота** живёт только в `apps/bot`, никогда в `@oover/shared` и не в `apps/web`.

## 7. Коммиты (Conventional Commits)

- Используй формат **Conventional Commits**: `<type>(<scope>): <описание>`.
- **Типы:** `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `style`, `perf`, `build`, `ci`.
- **Scope = затронутая часть монорепозитория:** `web`, `bot`, `shared`, `supabase`, `deps`, `docs`, `root`.
  - Примеры: `feat(web): добавить Kanban-борд`, `fix(shared): округление в convertToUah`, `feat(bot): команда /balance`, `chore(supabase): индекс на recurring_payments`.
- Описание — в повелительном наклонении, на английском, без точки в конце. Тело/футер — по мере необходимости (`BREAKING CHANGE:` помечай явно).
- Один коммит = одна логическая правка в рамках одной части. Не смешивай `web` и `shared` в одном коммите без причины.
